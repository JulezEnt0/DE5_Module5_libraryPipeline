# Architecture Decision Record

**Date:** 12/10/2026
**Status:** Accepted

## Context

Newham Public Library Network collects data from four sources in different formats: circulation (CSV), events (JSON API), member feedback (text files) and the digital catalogue (Excel). Analysts currently spend about 60% of their time cleaning data, and manual consolidation takes 2-3 days per month. There are no automated quality checks, so duplicates, missing values and inconsistent formats reach analysis.

The pipeline diagram shows how raw files move from the sources, through ingestion and cleaning, to analysis-ready outputs.

## Decision

We will use a medallion architecture with three layers:

- **Bronze:** raw data from all four sources, stored exactly as received with an ingestion timestamp.
- **Silver:** data cleaned and validated by our Python package. Records that fail validation checks are sent to quarantine and trigger alerts, rather than being silently dropped or passed on.
- **Gold:** analysis-ready aggregations that answer the library's key questions: popular books by borough, member retention rate, and event impact on visits.

Gold outputs feed Power BI, where row-level security restricts branch-specific data.

## Consequences

**Positive**

- Raw data is always preserved in bronze, so we can reprocess if cleaning logic changes.
- Silver is the trust boundary: gold always reads from silver, never bronze.


**Negative / trade-offs**

- Storing three copies of the data increases storage use and pipeline complexity.
- Any change to a schema in a source system needs to be handled at the bronze-to-silver step.
